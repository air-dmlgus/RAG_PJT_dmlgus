# ⚾ KBO INSIDE

**한 구단의 한 시즌을 선택하고, 출처가 있는 문서로만 야구 기록을 설명하는 RAG 서비스.**

AI 코어프로젝트 2회차 / 도메인: 한국프로야구 / 작성일: 2026-10-22

## 빠른 실행 — Windows

1. Python 3.10 이상을 설치한다. 설치할 때 Add Python to PATH를 선택한다.
2. ZIP을 풀고 `run_windows.bat`을 실행한다. 첫 실행에는 패키지 설치 시간이 필요하다.
3. 브라우저가 열리면 왼쪽 **100개 시즌 데이터 색인**을 누른다.
4. **기록 질문** 탭에서 구단·시즌을 고르고 `이 시즌 최종 순위는?`을 질문한다.
5. **시즌 탐색**에서 `2023년 우승 구단`을 입력하고 검색 결과의 선택 버튼을 누른다.

터미널에서 실행하려면 프로젝트 폴더 안에서 다음 명령을 사용한다.

```sh
python -m venv .venv
# Windows: .venv\Scripts\activate
# macOS/Linux: source .venv/bin/activate
python -m pip install -r requirements.txt
python -m streamlit run app.py
```

macOS/Linux에서는 `sh run.sh`도 가능하다. 기본 접속 주소는 http://localhost:8501 이다.

## 데모와 온라인 모드

기본값은 `KBO_MODE=demo`다. 데모는 실제 Chroma DB와 LangGraph를 사용하지만 **의미 임베딩과 LLM 호출 대신 로컬 문자 해시 벡터와 제한된 발췌 답변**을 사용한다. 수업의 LLM RAG 실행 증빙은 온라인 모드에서 별도로 확보해야 한다. 데모는 최종 순위·입문 가이드 답변, 연도·지역·구단명·N위·우승 조건 탐색을 지원한다. 그 외 질문은 확인 불가로 안내한다.

온라인 설정:

1. `.env.example`을 `.env`로 복사한다.
2. `KBO_MODE=online`, `OPENAI_API_KEY`, `CHAT_MODEL`, `EMBED_MODEL`을 설정한다.
3. SSAFY GMS를 사용한다면 `OPENAI_BASE_URL`과 모델명을 교육 안내의 실제 값으로 변경한다. OpenAI 호환 채팅·임베딩 API가 모두 필요하다. GMS 키/엔드포인트 호환성은 미검증이다.
4. 재시작하고 온라인 모드에서 다시 색인한다. 데모와 온라인 DB는 분리된다.
5. 위키백과 확장 검색을 켜려면 `WIKI_USER_AGENT`에 실제 연락처를 설정한다. 토큰·API 키를 연락처에 쓰면 안 된다.
6. 질문 화면에서 위키백과 자료 확장을 선택한다. 연결 제한 시 이를 끄고 제공 문서 모드를 사용한다.

외부 문서를 켜지 않아도 온라인 모드에서는 제공된 공식자료 요약을 검색하고 실제 LLM이 답한다. API 호출에는 설정한 제공자의 요금이 발생할 수 있다. 문서 확장은 여러 호출을 사용한다.

## 기능

- 필수: 100개 구단·시즌 항목 / 메타데이터와 문서의 2개 컬렉션 / 중복 방지 색인.
- 필수: 검색어 생성 → 후보 선별 → 수집·청킹·색인. 세 프롬프트를 분리했다.
- 필수: `retrieve → generate`의 두 LangGraph 노드 / 메타데이터 강제 포함.
- 필수: 실제 인용한 근거만 표시 / 출처 유형과 원문 링크 / 문서에 없는 사실은 확인 불가.
- 필수: 구단·시즌별 세션 내 대화 기록 / 자연어 조건 탐색 / 수집·생성 진행 안내.
- 도메인 특화: **시즌 입문 가이드**. 최종 순위와 순위 해석을 출처와 함께 설명한다.
- 선택 심화 **F2014**: MMR과 기본 유사도 검색을 같은 질문으로 비교한다.
- F2013 별도 HTML/JS 프론트, F2015 RAG 전후 품질 비교, F2016 이종 출처 통합은 선택하지 않았다.

## 데이터

2015~2024년 × 10개 구단 = **실재하는 100개 구단·시즌 항목**. 선수 100명이 아니라 구단의 특정 시즌 100개다. 당시 명칭인 SK 와이번스(2020년까지), 넥센 히어로즈(2018년까지)를 보존한다.

`data/items.json`: 시즌, 구단명, 구단 계보, 연고 도시, **최종 순위**, 원문 출처 등. 순위는 정규시즌 순위가 아니다. KBO 구단 변천사 표를 바탕으로 수작업 구성한 정적 데이터다. 현재 로스터·최근 순위·승률·승패·개인 기록은 포함하지 않는다.

`data/documents.json`: 각 항목 자체를 다루는 직접 작성 사실 요약 100개. KBO 공식 표의 순위 사실과 데이터 해석 범위를 기록했다. 원문 전체를 내려받은 자료가 아니며, 메타데이터와 같은 원자료에 기초해 지식 범위가 좁다. 외부 문서 호출 제한 시 대체 문서 묶음으로 사용한다. 풍부한 시즌 질문에는 위키백과 확장 또는 직접 확보한 합법적인 문서가 필요하다.

출처 및 이용 조건: [docs/SOURCES.md](docs/SOURCES.md). 로고·사진·기사 원문은 포함하지 않는다.

## 설정

`settings.json`의 `chunk_size=900`, `chunk_overlap=180`, `top_k=5`, `fetch_k=20`, `mmr_lambda=0.65`. top_k는 외부 문서 수이며 강제로 넣는 항목 메타데이터 1건이 추가된다. 수정 후 앱 재시작 및 문서 재색인을 수행한다. 기본 제공 요약은 짧으므로 청크 설정·MMR 차이가 작다. 위키백과 장문 문서를 수집한 뒤 비교해야 실제 다양성 차이를 관찰하기 쉽다.

## 검증과 제출

```sh
python -m scripts.index --twice
python -m unittest discover -s tests -v
```

테스트 결과와 미확인 항목은 [docs/VALIDATION.md](docs/VALIDATION.md)에 구분했다. `requirements-tested.txt`는 이번 환경에서 검증한 직접 의존성 버전이며 전체 전이 의존성 잠금 파일은 아니다. 첨부 명세의 고정 버전 조합과 다를 수 있으므로 교육 환경이 버전을 강제하면 그 환경에서 다시 검증해야 한다.

제출 전에 README의 지역·반·성명을 본인 것으로 작성하고 폴더를 `AI 코어프로젝트 2_KBO인사이드_지역_반_성명.zip`으로 압축한다. `.env`, `.venv`, `.runtime`, API 키는 제출하지 않는다. 공식 셀프·상호 체크리스트는 수업에서 제공받은 뒤 작성한다.

## 파일 구조

```text
app.py                 Streamlit UI
kbo/config.py          실행·검색 설정
kbo/data.py            100개 항목과 제공 문서 로드
kbo/collect.py         문서 수집·후보 선별·쿼리 캐시
kbo/store.py           임베딩·Chroma·재색인·MMR
kbo/prompts.py         세 프롬프트
kbo/llm.py             OpenAI 호환 API 호출·JSON 파싱
kbo/rag.py             LangGraph·근거 병합·조건 탐색
scripts/index.py       CLI 색인
 tests/                자동 검증
 docs/                 요구사항·설계·검증·출처
```

기록은 브라우저 세션 내에서만 유지된다. 새 세션·서버 재시작 후 유지되는 사용자 계정 기능은 없다. 답변 생성에 이전 턴을 넣지 않으므로 질문에는 구체적인 주어를 적는다. 인용 번호 검증은 연결성 검증이며 답변의 사실성을 자동 보증하지 않는다.
